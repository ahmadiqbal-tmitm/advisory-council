Agent #2 · Built in public

Advisory Council agent tutorial

Build your own council of advisors inside Claude in an afternoon. You describe it. Claude Code builds it.

Just want to use mine? Add the advisory council in about two minutes.

What you'll build

A connector for Claude with advisors you choose:

  • Each advisor has one field and answers in their own words.
  • You can ask one advisor, or the whole council.
  • On a council question, one advisor opens with a single question, sums up their understanding, then the others answer.
  • Anyone you share the link with can add it to their Claude.

Mine has Socrates, Sun Tzu, Marshall McLuhan and Marcus Aurelius. Yours can be anyone whose thinking you can write down: an author, a mentor, a founder you admire.

What you need

  • A Claude plan that includes Claude Code and custom connectors. Check claude.com/pricing.
  • The Claude desktop app. Claude Code is the Code tab inside it.
  • A free Cloudflare account. This is where your council will live.
  • A free GitHub account, if you want to share your code.
  • About three hours. Most of it is writing about your advisors, not building.

Four words you'll see

Connector
A plug that lets Claude reach something outside itself. Here, your advisors' material.
MCP server
The technical name for what sits behind a connector. You won't write one. Claude Code will.
Claude Code
Claude with the ability to create files and run them on your computer. You talk, it builds.
Deploy
Putting your council on the internet so Claude can reach it from anywhere.

Step 1: Choose your advisors (10 minutes)

Pick three or four people, and give each one field. The fields should not overlap.

  1. Advisor 1: ___ · field: ___
  2. Advisor 2: ___ · field: ___
  3. Advisor 3: ___ · field: ___
  4. Which one opens every council session with a question? ___

Why this matters: advisors with the same field give you the same answer three times. Different fields give you a real disagreement to think about.

Step 2: Write one document per advisor (30 minutes each)

This is the real work. Each advisor is only as good as the document behind them. In a normal Claude chat, paste this for each advisor:

Prompt
Help me write an advisor document for ___, whose field is ___.

Interview me one question at a time. Then write the document with these sections:

1. Field: what this advisor is for, and what they are not for.
2. Profile: who they were, in a few lines.
3. Core principles: 8 to 12, each with a plain-words meaning and where it comes from.
4. How they speak: tone, typical phrases, what they would never say.
5. Blind spots: where their thinking is weak or dated.
6. My modern context: how I apply their ideas to my own work and life.
7. Sources: what this is based on, and what you are unsure about.

Use only real sources. Do not invent quotations. Mark anything you are unsure of.

Save each one as a Markdown file. In Claude, use the menu on the document to export it.

Why this matters: your council does no thinking of its own. It hands this document to Claude, and Claude answers from it. A thin document gives you a generic advisor.

Tip: the "My modern context" section is what makes the advisor yours. Leave out anything you would not want strangers to read, because anyone with your link can ask for it.

Step 3: Give Claude Code my council to start from (10 minutes)

You don't start from a blank page. My council is public, and it is built so that adding an advisor takes one document and one entry in a list.

  1. Open the Claude desktop app and choose the Code tab.
  2. Pick an empty folder for your project and drop your advisor documents into it.
  3. Paste the prompt below.
Prompt
I want to build my own advisory council, based on this public project:
https://github.com/ahmadiqbal-tmitm/advisory-council

Copy that project into this folder. Then replace its four advisors with mine. My advisor documents are in this folder.

- Read its README.md and BUILD-LOG.md first.
- Put my documents in the advisors folder and update advisors.json to match.
- The advisor who opens every council session is ___.
- Remove the question sheets unless I give you my own.

I am not technical. Explain each step in plain words, and ask me before anything that can't be undone.

Why this matters: the hard parts are already solved in that project. You are changing who the advisors are, not how the council works.

Step 4: Test it on your computer (10 minutes)

Before anything goes online, ask Claude Code to prove it works:

Prompt
Run the council on this computer and run the local checks. Show me what each advisor's tool returns for this question: "___".

You are looking for three things: every advisor is listed, each one returns their own document, and an empty question gets a polite message.

Step 5: Put it online (15 minutes)

  1. Create a free account at cloudflare.com.
  2. Tell Claude Code: "Deploy this to Cloudflare."
  3. It will ask you to sign in to Cloudflare in your browser. Approve it.
  4. When it finishes, it gives you an address ending in /mcp. That is your council.

Why this matters: a council on your computer only works while your computer is on. Online, it works from your phone, and for anyone you share it with.

Step 6: Add it to Claude (2 minutes)

  1. In Claude, open Settings, then Connectors.
  2. Click Add custom connector and paste your address.
  3. Start a new chat and paste the prompt below with a real decision.
Prompt
Ask the council whether I should ___.

Step 7: Tune how it talks

Your first conversation will probably feel wrong. Mine did: long walls of text, and advisors described from the outside instead of speaking.

The fix is not code. The way the council talks lives in three plain-text files in the prompts folder. Tell Claude Code what felt wrong, in your own words:

Prompt
I tried the council and here is what I didn't like: ___.

Change the files in the prompts folder to fix it, deploy again, and tell me what you changed.

Then start a new chat and try again. Repeat until it sounds right.

Why this matters: this is where a working council becomes one you want to use. I changed mine once and it went from a report to a conversation.

What to try next

  • Add a question bank. A spreadsheet of questions and how the advisor would answer. Socrates and Marcus Aurelius have one in my council.
  • Give it your own address, like mine at advisorycouncil.ahmads.build. Ask Claude Code to add a custom domain.
  • Add it to a Project, so your other agents can call an advisor.

Why I built this

I had three real decisions in front of me: whether to join a partnership, how to start a workshop business, and whether to invest in a friend's company.

I wanted more than one opinion. So I built a council: four thinkers I keep going back to, each asked to look at the same question from their own field.

It took one afternoon with Claude Code. I wrote a brief describing what I wanted, and we built it together step by step.

What I learned

  • The documents are the advisors. Most of my time went into writing about each thinker, not into building.
  • The prompts are the product. When the first replies came back as walls of text, three plain-text files fixed it. The code never changed.
  • Advisors should speak, not be described. "Sun Tzu: you are choosing between…" reads like a conversation.
  • Tell Claude Code to check the current docs. My brief named a way of building that had been replaced a few weeks earlier. It caught that because I had asked it not to rely on memory.
  • Decide what is private before you go public. I took two personal details out of my documents before sharing the code.
  • Keep the server simple. Mine does no thinking and stores nothing, so it costs almost nothing to run.
